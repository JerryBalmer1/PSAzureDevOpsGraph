# v0.4.0 — the graph of a real project, committed

**Documentation and generated artifacts only. No `src/` file changed.**

## Why a docs-only minor exists

[Decision 0006](https://github.com/JerryBalmer1/AI.Agent.Claude.PowerShellModuleBuilder/blob/main/decisions/0006-target-versioning-and-tags.md)
prescribes an annotated `v0.<minor>.0` tag per plan that touches this
repository, with a worklog beside it, so every tag carries its reasoning. The
minor was determined from this repository's own `git tag` list and the
harness LEDGER's version line, which agreed: `v0.3.0` was the frontier, so this
is `v0.4.0`.

## What this tag ships

Before it, a stranger reading this repository was told the module answers *if I
change this template, which pipelines break?* and shown three snippets of
console output. Nothing let them see the answer, and nothing let them produce
one without an Azure DevOps account.

**What this tag ships is the graph of a real project, committed whole.**

`examples/` now holds the ClaudeTesting fixture as the module actually reads
it — 51 nodes and 51 edges across 15 pipelines, 30 YAML files and 4
repositories — as three artifacts:

| Artifact | What it is |
| --- | --- |
| [`examples/input/claudetesting-graph.json`](../../examples/input/claudetesting-graph.json) | The module's own output, in its own schema, unedited |
| [`examples/claudetesting.html`](../../examples/claudetesting.html) | That graph rendered through PSGraphRenderToHtml → PSGraphRender |
| [`examples/claudetesting.png`](../../examples/claudetesting.png) | A 1600x900 screenshot, and the README's hero image |

The README leads with the picture and an Examples table before it explains
anything.

## Two things the picture shows that prose did not

**The unresolved references are visible.** Both of them — the undeclared
`ghostTemplates` alias and the missing `templates/missing-steps.yml` — draw as
orange nodes with orange edges into them. The README has always claimed
unresolved references are reported rather than dropped; now that claim has a
picture attached.

**The dependency cycle names itself.** Four nodes — `p08-cycle`,
`pipelines/p08.yml`, `templates/cycle-a.yml`, `templates/cycle-b.yml` — have no
valid test order because each waits on another, and the report's sidebar says
so in those words. That the cycle is visible at all is a property of the
traversal: it records every edge *before* testing whether it has already
visited the target, so a cycle yields both its edges and still terminates.

## Reproducibility, and the token

The example rebuilds with one command from the repository root:

```powershell
pwsh -NoProfile -File examples/Build-Examples.ps1
```

That reads the live project, so it needs `$env:AZDO_PAT` to carry a token with
Code (Read) and Build (Read). The token is read from the environment by name
and is never written to a file, an argument, or a URL, which is the same rule
the module itself follows. Nothing committed under `examples/` contains a
credential or an absolute path.

The render step is separable, so a reader with no Azure DevOps account can
still rebuild the HTML from the committed graph:

```powershell
pwsh -NoProfile -File examples/Build-Examples.ps1 -Offline
```

## Still read-only

Generating this example issued `GET` requests and nothing else. No pipeline was
queued, run, or triggered, and nothing metered or billed. The module has no
parallelism, so the project was read one call at a time.

## The mapping lives in the example, not in the module

This module emits its own graph shape and does not depend on the render stack.
Rendering the graph therefore needs a mapping onto PSGraphRenderToHtml's
producer contract, and that mapping is in
[`examples/Build-Examples.ps1`](../../examples/Build-Examples.ps1) — **this tag
did not make this module depend on anything new.**

One case in that mapping is worth reading: two of the 51 edges point at targets
that are not nodes, because that is what makes them unresolved, and the
producer contract requires every edge endpoint to resolve. Carrying them means
inventing a node for the missing target. The first draft discarded them instead
and rendered 49 edges from a 51-edge graph — a graph that looked complete and
was not, losing exactly the two edges a reader most wants to see.
