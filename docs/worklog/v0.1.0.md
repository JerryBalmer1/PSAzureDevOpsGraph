# Worklog — v0.1.0

Why the module is shaped the way it is. What changed is in the changelog; this
is the reasoning that would otherwise have to be rediscovered.

## Parsing and resolution are two commands

The brief asks for it and the cost of merging them is concrete: a combined
command reports resolution failures as parsing results, and there is then no way
to tell which half was wrong. Parsing is testable against a file on disk with no
credentials, which is why most of this repository's tests need no PAT.

## `refKind` is written only on unresolved edges

The schema requires `ref`, `refKind` and `reason` on an `unresolved` edge and
makes all three optional elsewhere. On a resolved edge `kind` already **is** the
reference kind, so a second copy states nothing new — and an absent optional
field means *not stated*, which is a different and quieter claim than writing a
redundant value. Writing `refKind` everywhere would produce one difference per
edge against a hand-authored oracle on a module that was otherwise right.

The same reasoning puts `repo` and `path` on `yaml` nodes only, and omits `ref`
from `definition` edges, which are a claim about the Azure DevOps project rather
than about a file.

`alias` is written wherever the YAML carried one: on a `template`/`extends`
reference with an `@alias`, and on the local handle a `resources.repositories`
or `resources.pipelines` entry declares. On a `checkout` the reference text *is*
the alias, so writing it twice says nothing and it is omitted. That asymmetry is
deliberate; it is the line between "here is a fact you could not otherwise read
off the edge" and "here is the same string again".

## Unresolved targets are edges without nodes

An `unresolved` edge points at a synthesised id — `yaml:@ghostTemplates/x.yml`
for an undeclared alias — and no node is emitted for it. Two reasons: the id
must not collide with a real node, and a `yaml` node is required to carry `repo`
and a `path` starting `repos/`, which an undeclared alias cannot supply. The
HTML and DOT exports synthesise pseudo-nodes at render time instead.

## The repositories endpoint is a lookup table

It is called once, to turn a repository name into something the items route can
use and to know which names exist. It does **not** produce nodes. A graph with a
node per repository in the project answers "what is in this project" instead of
"what do these pipelines depend on", and only the second question makes the
brief's question answerable.

## powershell-yaml is in the manifest, not in Requirements.psd1

It is a runtime dependency: a machine that imports this module needs it whether
or not it ever runs a build. `Requirements.psd1` holds build tools only. Writing
a dependency in both files creates two facts that must agree and are edited in
different places.

## Coverage target

70%, declared once to Pester and read back off the result by the gate, so there
is one number rather than two that must agree. The REST error branches are
covered by mocking `Invoke-WebRequest` rather than by lowering the target.
