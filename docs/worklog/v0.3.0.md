# v0.3.0 — the measurement history reaches the measured repository

**Documentation only. No score is re-earned here, and none is new.**

## Why a docs-only minor exists

[Decision 0006](https://github.com/JerryBalmer1/AI.Agent.Claude.PowerShellModuleBuilder/blob/main/decisions/0006-target-versioning-and-tags.md)
prescribes an annotated `v0.<minor>.0` tag per plan that touches this
repository, and a worklog beside it, so that every tag carries its reasoning.
It does not carve out an exception for a plan whose whole output is prose, and
this file is not the place to invent one. The minor was assigned in the pass
prompt, as decision 0006 requires.

So the question is not *does this deserve a tag* but *what does this tag ship*,
and the answer is a claim change. Before it, this repository said it had been
built as run 002 and quoted run 002's three scores. Five further runs had
happened since — three plugin-on, one plugin-off control with the same
iteration budget, and one earlier control never permitted a fix loop — and none
of them was mentioned anywhere a reader of this repository would look. The
harness knew; the repository the harness measured did not.

**What this tag ships is the measurement history reaching the measured repo,
with each number bounded exactly as the harness bounds it.**

`README.md`'s `Install` section also changed, and it is worth naming rather
than burying. It told the reader to
`git clone --branch run-002-first-build` and closed with *"This is a branch,
not a release."* Both statements were true when written and are now false in a
way that matters: `run-*` branches are the **measurement** line, orphan roots
that are never merged and never tagged, and decision 0008 has since made `main`
follow the tags. An install instruction pointing at a measurement branch
invites exactly the confusion the two-line distinction exists to prevent.

## Every claim moved down or sideways, never up

The rule the pass worked under. Three worth stating:

- **Run 002's 12/12 is no longer quoted without its caveat.** The run's own
  record has always carried a standing block-quote saying it is not a
  zero-skill baseline — the plugin was seeded before it and the builder read
  the fixture's case list as a specification. The README quoted the number and
  not the caveat. It now carries both.
- **"With the plugin and without it" is now the control's sentence, not a
  stronger one.** The claim is that the plugin buys **shape, not correctness**:
  all four runs permitted to iterate reached 12/12, and what the plugin
  reliably supplies is first-shot conformance to house style, 19/33 → 33/33.
  The control's first shot was the *closest* of the four on the functional
  score. That is a smaller claim than "the plugin makes the module right", and
  it is the one the evidence carries.
- **The 28/33 is printed with the 32/33 beside it, and the reason.** Four
  `RequiresBuild` assertions read a gitignored build directory, so a clone that
  was never built fails them. Run 007's conformance clone was not built. Both
  numbers are printed because the defect was in the scoring procedure rather
  than in either module, and hiding the worse one would be the wrong
  correction.
